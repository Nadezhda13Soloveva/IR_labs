# ЛР 2: Поисковый робот

## Тематика корпуса: Информационная безопасность

**Цель:** Разработать краулер-программу, которая сама ходит по выбранным источникам, скачивает статьи и кладёт их в базу

---

### Общий алгоритм

Краулер работает так:

1. Берёт из очереди следующий URL.
2. Ждёт паузу (`delay`), чтобы не долбить сайт.
3. Скачивает страницу.
4. Сохраняет её в MongoDB.
5. Достаёт со страницы новые ссылки на статьи и добавляет их в очередь.
6. Повторяет, пока очередь не кончится или не достигнут лимит страниц.

Очередь URL (frontier) тоже лежит в MongoDB. Поэтому если нажать Ctrl+C или процесс упал, при следующем запуске робот видит, что ещё не скачано, и продолжает.

```
YAML-конфиг
    |
Очередь URL (frontier)  ->  скачать  ->  документы (HTML)
    ^                                      |
    |________ новые ссылки со страницы ____|
```

---

### Что хранится в базе

**Документ страницы** (коллекция `documents`):

| Поле | Смысл |
|------|--------|
| `url` | Адрес без мусора (`utm_`, лишних `/` и т.д.), уникальный |
| `raw_html` | Полный HTML, как пришёл с сайта |
| `source` | Откуда: `habr`, `xakep`, `securitylab`, … |
| `crawled_at` | Когда скачали - число секунд с 1970 года |
| `content_hash` | Отпечаток содержимого - чтобы понять изменилось / нет |

**Очередь** (коллекция `frontier`): URL, источник, статус (`pending` / `in_progress` / `done` / `error`)

*Отпечаток и статусы у нас служебные поля: без них нельзя нормально сделать умную переобкачку

---

### Конфиг

Программе передаётся только путь к YAML:

```
python -m crawler.main config.yaml
```

В конфиге три блока:

- `db` — куда писать (MongoDB);
- `logic` — пауза между запросами, лимит страниц, через сколько дней перепроверять старое;
- `sources` — стартовые ссылки, разрешённые домены, CSS-селекторы ссылок на статьи (из разбора ЛР1)

---

### Resume (продолжение после остановки)

1. URL берётся из frontier со статусом `pending` и помечается `in_progress`
2. После успеха — `done`, при ошибке — снова `pending` или `error`
3. При старте все зависшие `in_progress` возвращаются в `pending`

*Очередь не в памяти, а на диске (в Mongo), т.е. перезапуск безопасен

---

### Переобкачка (только если изменилось)

1. Страницы старше N дней снова попадают в очередь
2. При запросе робот отправляет eTag
3. Ответ 304 или тот же hash HTML -  HTML не трогаем, только обновляем время проверки
4. Если HTML другой - перезаписываем документ

---

### Как запустить

```
cd lab_2
pip install -r requirements.txt
# MongoDB должна быть запущена на localhost:27017
python -m crawler.main config.yaml
```

Остановка: Ctrl+C. Повторный запуск - продолжение с того же места.
